# 角色规范（ROLE-SPEC）

每个角色 = **6 层画像**。质量差距来自角色定位深浅——写得好，agent 抓到的都是真问题；写得浅，agent 泛泛而谈。

## 6 层画像

| 层 | 作用 | 示例 |
|---|---|---|
| **identity** 身份 | 这个角色是谁、在乎什么 | "第一次来网站的完全新手，不想读文档，只想快速完成任务" |
| **vision** 专业视角 | 它怎么看页面（不是看信息密度，而是看"能不能走下去"）| "我走一遍核心任务：每一步是否自然、是否被吓退" |
| **checklist** 硬清单 | 逐条执行、命中才报（可操作）| "①30秒冷启动 ②主路径 ③术语墙 ④文案矛盾 ⑤信任信号" |
| **kpi** 什么叫合格 | 什么算失败/成功 | "发现真会卡住新手的" |
| **constitution** 原则锚点 | 依据什么原则（违规才报）| "主路径清晰·免责声明" |
| **defense** 误报防御 | 避免凑数（明确不报什么）| "别把信息密度高当缺点" |

## 角色分类

- **巡检角色**（发现痛点）：新手/老手/数据审计/合规/性能/视觉/无障碍/SEO/转化/安全/内容… 每个有 `w`（专属加权维度）
- **决裁角色**（`judge:true`）：对每条提案独立复核，`veto` 字段锁一票否决维度
- **最终裁判**（`judge:true, final:true`）：最高原则，不可覆盖

## 配置字段

```js
{
  key: "new-user",          // 唯一标识
  name: "新手用户",          // 显示名
  w: { D: 3 },              // 专属加权：该角色发现的问题，D 维度 ×3
  scope: ["all"],           // 覆盖页面类别（"all" = 所有核心页）
  judge: false,             // true = 参与决裁
  veto: "T",                // 该角色锁死的一票否决维度
  identity / vision / checklist / kpi / constitution / defense  // 6 层画像
}
```

## 评分维度（默认 10 维）

| key | 名称 | 一票否决 |
|---|---|---|
| D | 决策转化 | - |
| C | 内容质量 | - |
| M | 变现 | - |
| T | 数据可信 | ≥4 |
| R | 零风险 | ≥4 |
| S | 单人可维护 | ≥3 |
| F | 目标一致 | ≥1 |
| P | 性能成本 | - |
| U | 体验 | - |
| G | 增长 | - |

可在 `config.dims` 增删维度；`scoreOf` 自动按维度计算总分与一票否决。

## 写角色的 4 条铁律

1. **清单要可操作**：别说"检查体验"，说"首屏最重要内容是否最突出"
2. **defense 要具体**：明确"不报什么"，agent 才不凑数
3. **constitution 要能裁决**：违规才报，且给出"能修/需授权"的区分
4. **专属加权要准**：数据审计官 T×3（它是数据守门人），别给 UI 角色 T×3
